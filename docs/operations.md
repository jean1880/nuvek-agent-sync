# Operations

## How agent-sync writes

- **Files agent-sync writes itself** (settings, generated agents, `AGENTS.md`, hook and MCP
  files, `managed.json`) are written to a new temporary file in the same directory, created
  exclusively under a random name, then renamed over the old file. The file is either the old
  version or the new one, never half-written. The previous version is kept as
  `<file>.agent-sync.bak` (one generation, written the same way). A write that contains a
  secret-shaped token is refused.
- **Links** are replaced by renaming a fresh link over the old one, so they are never missing.
- **`~/.claude.json` MCP servers** are registered through the `claude mcp` CLI. agent-sync does
  not write that file, except to create it with no servers on a fresh machine, and it keeps no
  backup of what the CLI changes.
- **A run is not a transaction.** Each file is replaced atomically, but `apply` writes several
  files in turn. If it stops partway, some tools are updated and others are not, and the next
  `apply` finishes the job.
- **Symlinks and directories.** A destination that is itself a symlink is refused: agent-sync
  replaces files, it does not write through links. A tool directory may be a symlink (for
  example `~/.claude` kept in a dotfiles checkout), but only if it resolves inside a directory
  agent-sync manages. Those are `~/.claude`, `~/.gemini`, `~/.codex`,
  `$XDG_CONFIG_HOME/agent-terminal`, its own state directory, the source's `sync/` (for `import`
  and `promote --add`, without an overlay) and the `.agents/` and `.git/info/` of repositories
  with a private overlay file. A write anywhere else is refused.
- **One writer at a time.** `apply`, `import` and the writing forms of `promote` hold an
  exclusive lock on `$XDG_STATE_HOME/agent-sync/lock` for their whole run. A second run waits.
  `check` takes no lock and writes nothing.
- **Ownership.** At the end of every `apply`, `$XDG_STATE_HOME/agent-sync/managed.json` records
  the links and generated agent files agent-sync made. Only an entry listed there is ever
  deleted: a stale link that still points where agent-sync pointed it, or a generated agent
  whose source is gone. The first run, with no manifest yet, deletes nothing. It adopts what
  matches what it creates.

## Behaviour notes

- **Generated headers name the source.** Rendered agents and `~/.codex/AGENTS.md` say
  `GENERATED by agent-sync from <source>`. `<source>` is the `--dir` checkout (written as `~/…`
  under `$HOME`), or the agent's own file in it.
- **A fresh machine is drift, not an error.** A missing tool file is reported as `missing`
  (exit 6), and `apply` creates it. A missing `~/.claude.json` is created with an empty
  `mcpServers`.
- **`import` seeds a neutral `map.toml`:** the standard tiers and tool names, with no
  placeholder names and no `not_projected` notes.
- **Deletion needs ownership.**
  - Stale links and orphaned generated agents are deleted only when `managed.json` lists them.
    An agent file must also still carry its generated header.
  - A generated agent that is not listed is left in place and reported as drift ("not recorded
    in managed.json"). Until you remove it by hand, `check` exits 6 and `apply` cannot converge.
  - An unreadable or corrupt `managed.json` stops `apply` and is reported by `check`. Deleting
    it starts fresh, and the next run then deletes nothing.
- **Symlinked destinations are refused.** If a dotfile manager links
  `~/.claude/settings.json`, `~/.claude.json` or `~/.codex/config.toml`, `apply` stops with an
  error rather than replacing the link with a file. A real file where a link belongs is refused
  before anything is changed.
- **Output is scrubbed.** Everything printed and logged, error chains included, passes through
  the redactor. An MCP server whose name looks like a secret is never put on the `claude`
  command line.
- **`promote` exits 5 when `agy` is running**, as `apply` does.
- **Agent names are checked.** An agent name must be one plain file name
  (`[A-Za-z0-9._-]+`, not starting with a dot) that matches its file. `import` checks every name
  before it writes anything.

## Paging on drift from systemd

`check` only reports. To be told when a machine drifts, run it from a timer and let systemd page
on failure. A drift exits 6, so the service fails and `OnFailure=` runs:

```ini
# ~/.config/systemd/user/agent-sync-check.service
[Unit]
Description=agent-sync drift check
OnFailure=agent-sync-alert.service

[Service]
Type=oneshot
ExecStart=/usr/bin/agent-sync check
```

```ini
# ~/.config/systemd/user/agent-sync-check.timer
[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target
```

```ini
# ~/.config/systemd/user/agent-sync-alert.service
[Service]
Type=oneshot
# Any notifier: notify-send, a webhook script, mail. Send item names only; the drift output can
# quote configuration.
ExecStart=/usr/bin/notify-send "agent-sync" "Agent configuration drifted: run agent-sync check"
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now agent-sync-check.timer
```

## Recovery

A projection that breaks an agent comes from the source: `git revert` the change in the checkout,
then `agent-sync apply`.

To recover a single file, copy its `<file>.agent-sync.bak` back. That backup is only the version
before the last write.

With an overlay, the previous resolved tree is kept under `$XDG_STATE_HOME/agent-sync/generations/`.
Running `apply` again after the revert rebuilds the tree.
